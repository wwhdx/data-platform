## 2. 依赖关系分析

```
A2 (paginateOffset)
  ├── A3 (World Bank Connector)  ← 依赖 A2
  └── A4 (Semantic Scholar)      ← 不依赖 A2，有自己的分页

A1 (批量消费) — 无依赖，独立改动

B1-B5 (配置热更新 P0) — 无依赖，独立模块

B6 (Connector 读数据库) ← 依赖 B1+B3（配置文件+表结构就位）

C1-C2 (Docker + Client) — 无依赖，独立改动，但与 data-platform 内部改动并行

C3 (engine-core 注入) ← 依赖 C2（Client 就位）+ data-platform 至少有 3+ Connector 有数据可搜
```

**关键路径**：A2 → A3（World Bank 是第一个用 offset 分页的 Connector）。

**独立可并行**：A1（批量消费）和 B1-B5（配置热更新）和 C1-C2（Docker 部署）三者互不依赖。

## 3. 推荐实施方案

### 第一周：data-platform 核心夯实

**目标**：3 个 Connector 就位 + 配置可运维 + 采集性能翻倍

#### Day 1-2：配置热更新 P0

```
B1  config/sources.yml 模板       ─→ 一份 YAML 呈现全部数据源
B2  YAML 加载器 (src/config/)      ─→ 启动时自动同步到数据库
B3  data_sources.updated_at        ─→ 迁移
B4  PUT /api/admin/sources/:id     ─→ API 配置更新
B5  config_audit_log 表            ─→ 迁移
```

**交付**：`pnpm cli config list` 能看到所有数据源状态；`curl -X PUT /api/admin/sources/crossref -d '{"baseUrl":"..."}'` 能更新配置并记录审计日志。

#### Day 3-4：World Bank Connector（零认证，快速验证 Connector 模板）

```
A2  BaseConnector.paginateOffset()   ─→ 通用 offset 分页方法
A3  WorldBankConnector                ─→ REST + 无认证 + offset 分页
    - search: GET /v2/country/all/indicator/{code}?format=json
    - collect: 遍历指标代码列表，批量拉取观测值
    - 注册: connectors/index.ts, index.ts, 005_worldbank.sql
    - 测试: ~15 tests
```

**交付**：3 个 Connector 就位（OpenAlex + CrossRef + World Bank），覆盖学术 + DOI + 经济指标三大领域。

#### Day 5：采集性能 + 收尾

```
A1  Scheduler 批量消费（缓冲 200 条）
    ─→ runCollection() 改动 10 行
    ─→ 200 次 DB 往返 → 1 次
```

**交付**：采集吞吐量提升 ~200 倍（对大批量源）。

### 第二周：Connector 扩展 + 配置完善

## 5. 不做的事（明确排除）

| 排除项 | 理由 |
|--------|------|
| Embedding 队列化 | 日均采集量 < 1000 条时不需要，当前 fire-and-forget + 日志够用 |
| Stage 3 段落级分块 | 需要先有长文本数据（当前仅 title+abstract），分块策略收益有限 |
| Stage 2 LLM 富化 | 属于 engine-core 侧能力，data-platform 只做规则/NER 轻量抽取 |
| `/api/context` 端点 | 已明确移除，由 engine-core summarizeContext 替代 |
| 知识图谱 (Neo4j) | Phase 3，需要 Connector 覆盖先到位 |

## 6. 风险与缓解

| 风险 | 缓解 |
|------|------|
| World Bank API 无限制 → 可能被限流 | `paginateOffset` 中每页之间加 `sleepMinInterval` |
| Semantic Scholar 商业授权未完成 | 默认 `enabled: false`，仅开放给非商业使用 |
| YAML 解析库新增外部依赖 | `js-yaml` 是 Node.js 生态事实标准，零原生依赖 |
| 配置文件与数据库不同步 | `config diff` 命令 + 启动时 `config validate` 检查 |
