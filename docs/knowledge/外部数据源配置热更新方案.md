# 外部数据源配置热更新方案

> 设计分析 · 2026-05-15
> 应对：外部 API URL 变更、速率限制调整、认证方式升级等不可控因素

---

## 1. 现状诊断

### 1.1 配置散落三处，无单一真源

```
Connector 元数据    → TypeScript 硬编码 (connectors/crossref.ts META)
数据库注册          → PostgreSQL data_sources 表 (migrations/004_crossref.sql)
环境变量            → .env (CROSSREF_MAILTO, OPENALEX_API_KEY)
```

**问题**：三处各自独立，改一个 URL 需要：
1. 找到对应 Connector 的 TypeScript 文件
2. 修改 `META` 常量
3. 修改数据库迁移中的 INSERT（或 psql 手动 UPDATE）
4. `pnpm build` → 重新构建 Docker 镜像 → 重启服务

**运维人员不可能直接改 TypeScript 源码。**

### 1.2 当前 data_sources 表利用率低

```sql
-- 表已存在，字段覆盖 ConnectorMeta 的大部分
CREATE TABLE data_sources (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    base_url TEXT NOT NULL,       -- ← 对应 META.baseUrl
    auth_type TEXT NOT NULL,       -- ← 对应 META.authType
    rate_limit TEXT,              -- ← 对应 META.rateLimit
    license TEXT NOT NULL,        -- ← 对应 META.license
    commercial_use BOOLEAN,       -- ← 对应 META.commercialUse
    status TEXT NOT NULL DEFAULT 'active',
    created_at TIMESTAMPTZ
);
```

**但 Connector 从不读这张表。** `META` 对象在 TypeScript 中硬编码，数据库表仅用于 `/api/sources` 展示和 `/api/health` 统计，完全浪费了运行时配置能力。

### 1.3 运维场景枚举

| 场景 | 频率 | 当前处理方式 | 理想处理方式 |
|------|------|------------|------------|
| API Base URL 变更 | 低（年/次） | 改代码 → 构建 → 部署 | API 调用更新 → 即时生效 |
| 速率限制收紧 | 中（季度） | 改 RateLimiter 参数 → 构建 | API 调用更新 → 即时生效 |
| 认证方式升级 | 低（年） | 改 authType + auth 逻辑 → 构建 | 需代码改动（认证逻辑变更） |
| API Key 轮换 | 高（月/次） | 改 .env → 重启 | ✅ 环境变量已支持 |
| 临时禁用某源 | 中 | 改 status 字段 | ✅ 数据库已有 status 字段 |
| API 响应格式变更 | 中 | 改字段映射 → 构建 | 需代码改动（映射逻辑变更） |

**结论**：配置型变更（URL、限速、开关）应运行时可控。逻辑型变更（认证流程、字段映射）必须代码改动。两者的边界就是运维自助的边界。

## 2. 方案设计

### 2.1 配置优先级链

```
环境变量 (最高优先级, 紧急覆盖)
    ↓ 覆盖
数据库 data_sources 表 (API 即时更新, 运行时生效)
    ↓ 覆盖
配置文件 sources.yml (运维批量管理, git 版本控制)
    ↓ 覆盖
TypeScript META 常量 (出厂默认值)
```

四层各自定位：
| 层 | 修改方式 | 生效方式 | 适用场景 |
|----|---------|---------|---------|
| 环境变量 | `vi .env` | 重启 | API Key 轮换、紧急 URL 覆盖 |
| 数据库 | API/CLI | 即时（下次请求刷新缓存） | 运维日常调整、自动化告警联动 |
| 配置文件 | `vi config/sources.yml` | 重启或 `--sync-config` | 批量修改、git 版本对比、新人了解全貌 |
| META 常量 | 修改源码 → 构建 | 部署 | 新增 Connector 时的出厂默认值 |

### 2.3 配置文件与数据库的同步

```
┌────────────────────┐
│ config/sources.yml │  ← git 版本控制, 人类可读, 运维编辑
└────────┬───────────┘
         │ 启动时自动加载 / CLI 手动触发
         ▼
┌────────────────────┐
│ data_sources 表     │  ← 运行时真源, API 可更新
└────────┬───────────┘
         │ Connector 读取
         ▼
┌────────────────────┐
│ resolveBaseUrl()   │  ← 合并: env > db > file > META
└────────────────────┘
```

**启动时同步逻辑**：

```typescript
// src/index.ts — startup
import { syncConfigFromYaml } from "./config/sync";

// 启动时自动同步配置文件到数据库
// 策略：INSERT ON CONFLICT DO UPDATE（但只更新配置文件中有值的字段）
await syncConfigFromYaml("config/sources.yml");
```

**同步策略**（CLI 提供三种模式）：

```bash

# 输出：
#   crossref:
```

**配置校验**：启动时校验 YAML 结构：
- `id` 必须在 Connector 注册表中有对应实现
- `auth_type` 必须是已知枚举值
- `schedule` 必须是合法 cron 表达式
- `license` 不能为空（合规要求）
- 不允许重复 `id`

### 2.5 改造点 1：Connector 从数据库读配置

```typescript
// src/connectors/base.ts — 新增
import { query } from "../storage/db";

interface RuntimeConfig {
  baseUrl: string;
  authType: string;
  rateLimit: string;
  license: string;
  commercialUse: boolean;
}

export abstract class BaseConnector implements Connector {
  abstract readonly meta: ConnectorMeta;  // 出厂默认值（保留）

  private runtimeConfig: Partial<RuntimeConfig> | null = null;

  /**
   * 合并后的有效配置：环境变量 > 数据库 > META 默认值。
   * 在首次使用时惰性加载数据库配置。
   */
  protected async resolveBaseUrl(): Promise<string> {
    const db = await this.getDbConfig();
    return process.env[`${this.meta.id.toUpperCase()}_BASE_URL`]
      ?? db.baseUrl
      ?? this.meta.baseUrl;
  }

  protected async resolveRateLimit(): Promise<string> {
    const db = await this.getDbConfig();
    return process.env[`${this.meta.id.toUpperCase()}_RATE_LIMIT`]
      ?? db.rateLimit
      ?? this.meta.rateLimit;
  }

  private async getDbConfig(): Promise<Partial<RuntimeConfig>> {
    if (this.runtimeConfig) return this.runtimeConfig;

    try {
      const result = await query(
        `SELECT base_url, auth_type, rate_limit, license, commercial_use
         FROM data_sources WHERE id = $1`,
        [this.meta.id],
      );
      if (result.rows.length > 0) {
        const row = result.rows[0]!;
        this.runtimeConfig = {
          baseUrl: String(row.base_url),
          authType: String(row.auth_type),
          rateLimit: String(row.rate_limit ?? ""),
          license: String(row.license),
          commercialUse: Boolean(row.commercial_use),
        };
      }
    } catch {
      // 数据库不可达时降级为 META 默认值
    }

    return this.runtimeConfig ?? {};
  }

  /** 清除缓存，强制下次重新读取数据库（配合配置更新使用） */
  invalidateConfig(): void {
    this.runtimeConfig = null;
  }
}
```

### 2.6 改造点 2：管理 API — 配置更新端点

```
PUT /api/admin/sources/:id    — 更新数据源配置
```

```typescript
// src/api/routes/admin.ts — 新增端点

interface UpdateSourceBody {
  baseUrl?: string;
  authType?: string;
  rateLimit?: string;
  license?: string;
  commercialUse?: boolean;
  status?: "active" | "degraded" | "error" | "disabled";
}

app.put("/sources/:id", async (req, reply) => {
  const { id } = req.params as { id: string };
  const body = req.body as UpdateSourceBody;

  // 白名单：只允许更新运维可控字段
  const allowedFields = [
    "base_url", "auth_type", "rate_limit",
    "license", "commercial_use", "status",
  ];

  const sets: string[] = [];
  const params: unknown[] = [id];

  for (const [key, field] of [
    ["baseUrl", "base_url"],
    ["authType", "auth_type"],
    ["rateLimit", "rate_limit"],
    ["license", "license"],
    ["commercialUse", "commercial_use"],
    ["status", "status"],
  ] as const) {
    if (body[key] !== undefined) {
      sets.push(`${field} = $${params.length + 1}`);
      params.push(body[key]);
    }
  }

  if (sets.length === 0) {
    return reply.status(400).send({ error: "no fields to update" });
  }

  const result = await query(
    `UPDATE data_sources SET ${sets.join(", ")}
     WHERE id = $1
     RETURNING *`,
    params,
  );

  if (result.rows.length === 0) {
    return reply.status(404).send({ error: "source not found" });
  }

  // 通知 Scheduler 清除对应 Connector 的配置缓存
  app.scheduler?.invalidateConnectorConfig(id);

  return reply.send({ ok: true, source: result.rows[0] });
});
```

### 2.8 改造点 4：健康检查增强

当前健康检查只统计文档数，不探测外部 API 连通性。需要增加**外部 API 探活**：

```typescript
// src/api/routes/health.ts — health check 增强

async function probeSourceHealth(source: {
  id: string; baseUrl: string; status: string;
}): Promise<SourceStatus> {
  if (source.status === "disabled") {
    return { /* ..., */ status: "disabled", totalDocuments: 0 };
  }

  try {
    // 轻量探测：HEAD 请求 + 超时 5s
    const res = await fetch(source.baseUrl, {
      method: "HEAD",
      signal: AbortSignal.timeout(5000),
      headers: { "User-Agent": "WangyeDataPlatform/0.1 (health-check)" },
    });

    return {
      /* ..., */
      status: res.ok ? "healthy" : "degraded",
      healthCheck: { ok: res.ok, latencyMs: 0, errorMessage: res.ok ? undefined : `HTTP ${res.status}` },
    };
  } catch (err) {
    return {
      /* ..., */
      status: "error",
      healthCheck: { ok: false, latencyMs: 0, errorMessage: String(err) },
    };
  }
}
```

**告警规则**：
- 连续 3 次健康检查失败 → 状态自动标记为 `degraded`
- 状态为 `error` 时 → Scheduler 跳过该源的定时采集
- 恢复后自动切回 `active`

## 6. 配置优先级矩阵总结

```
某个 Connector 的 base_url 字段最终值的确定顺序：

1. 检查环境变量 CROSSREF_BASE_URL
   ├── 有值 → 使用（最高优先级，需重启，紧急覆盖）
   └── 无值 ↓

2. 查询 data_sources WHERE id = 'crossref'
   ├── 有值 → 使用（运维通过 API/CLI 设置，即时生效）
   └── 无值 ↓

3. 读取 config/sources.yml 中 crossref.base_url
   ├── 有值 → 使用（启动时同步到数据库，git 版本控制）
   └── 无值 ↓

4. 使用 TypeScript META.baseUrl
   → 使用（出厂默认值，保证零配置可运行）
```
