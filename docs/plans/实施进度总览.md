## 4. 下一阶段任务计划（2026-05-19 定稿）

> 详排期与风险见 [下一阶段实施方案 §3](./下一阶段实施方案.md#3-推荐实施方案)。  
> **已完成（勿重复排期）**：B1–B5、B9–B12、B6/B7（合入 B10/B11）、A1–A3、A6、E2E。

### 4.1 结构性缺口（驱动优先级）

| 缺口 | 现状 | 对应任务 |
|------|------|----------|
| **平台断层** | 父仓无 `DataPlatformClient`；engine-core 未注入 `searchProvider` | **C2 → C3** |
| ~~调度与 YAML 脱节~~ | ~~硬编码 cron~~ | **B13** ✅ 路线 A：`registerSchedulesFromConfig` |
| **采集重复/粗糙** | 无 `last_collected_at`；`collect({})` 未传 `since` | **A5** |
| **RAG 精度** | 每文档 1 chunk；embedding fire-and-forget | **A8**（A9 暂缓） |

**调度注意**：仅 `registerConnector` 不会 cron 采集；`scheduler.schedule()` 且不看 YAML `enabled` 会导致「配置关闭仍定时跑」。B13 目标：`enabled: true` + 有 Connector + 合法 `schedule` 才注册 cron。

### 4.2 三轨并行

```
轨 1 平台价值（父仓 + engine-core）     轨 2 数据面（本子包）           轨 3 质量/运维
─────────────────────────────────   ───────────────────────────   ──────────────────
C2 DataPlatformClient               A5 last_collected_at           B8 API 探活
        │                           B13 YAML 驱动 cron                    │
        ▼                           A4 Semantic Scholar              A8 段落分块
C3 searchProvider 注入              A7 arXiv OAI（P2）              C4 admin 页（P2）
```

轨 1 与轨 2 **可并行**（不同仓库/目录）；轨 3 建议在有一定入库量后做 A8。

### 4.3 任务优先级与工作量

| 优先级 | ID | 条目 | 工作量 | 依赖 | 交付验收 |
|--------|-----|------|--------|------|----------|
| **P0** | C2 | 父仓 `DataPlatformClient` | ~1d | data-platform API 可用 | `search()` 调通 `POST /api/search` |
| **P0** | C3 | engine-core 注入 data-platform | ~0.5d | C2 | 工作流可选知识库检索 |
| **P1** | A5 | `last_collected_at` 持久化 | ~1d | — | 二次采集 `since` 收窄 |
| ~~P1~~ | B13 | YAML 驱动调度 | ✅ | B9–B11 | `scheduler/bootstrap.ts`；worldbank disabled 不 cron |
| **P1** | A4 | Semantic Scholar Connector | ~1d | profile 已有 | `SEMANTIC_SCHOLAR_API_KEY`；默认 disabled |
| **P2** | B8 | 各源外部 API 探活 | ~0.5d | — | `/health` 反映源可达性 |
| **P2** | A8 | `processors/chunk.ts` 分段 | ~1d | 有长文数据 | 论文多 chunk 检索 |
| **P2** | A7 | arXiv OAI-PMH（`arxiv_oai`） | ~1.5d | B9 profile | 与 Legacy `arxiv` 并存 |

### 4.4 推荐两周排期

#### 第 1 周：平台闭环 + 采集基础

| 日 | 任务 | 产出 |
|----|------|------|
| 1–2 | **C2 + C3** | 父仓 client + engine-core `searchProvider` |
| 3 | **A5** | 迁移 + scheduler 使用 `last_collected_at` / `since` |
| 4 | ~~**B13**~~ | ✅ `registerSchedulesFromConfig`（路线 A） |
| 5 | 联调 | engine-core → data-platform 检索 E2E；更新 §2 真源 |

#### 第 2 周：扩源 + 质量（二选一深化）

| 日 | 任务 | 产出 |
|----|------|------|
| 1–2 | **A4** | `semanticscholar.ts` + bootstrap 注册 |
| 3 | **B8**（可选） | health 探活 |
| 4–5 | **A8** 或 **A7** | 检索质量（分块）或预印本覆盖（OAI） |

### 4.5 按目标选型

| 若目标是… | 先做 |
|-----------|------|
| 望野生成/审校能用知识库 | **C2 → C3** |
| 少重复采、省配额 | **A5 → B13** |
| 多源论文 | **A4** |
| 运维配置即调度 | **B13** |
| 检索效果明显变好 | **A8**（有数据后） |

### 4.6 明确不做（近期）

| 排除项 | 理由 |
|--------|------|
| A9 Embedding 队列 | 日均量小；日志 + 手工重跑够用 |
| 12 源 Connector 齐做 | ROI 低；平台未接前优先 C2–C3 |
| 无 B13 仅 `enabled: true` pubmed | 仍无 cron 或手写 cron 与 YAML 矛盾 |
| Stage 2 LLM 富化 | 属 engine-core；本子包仅轻量规则 |

**配置运维路径**：`pnpm cli config validate` → 改 YAML → `pnpm cli config sync`（或 restart app 自动 sync）。
