## 1. 目标与范围

在 `tx-cloud` 上部署 **`https://report.farview.cn`**，用于：

- **今日运行体检**：调度、覆盖、采集、字段、新鲜、配置六项，回答「今天的功能是否正确」；
- **今日采集内容浏览**：按类型/行业浏览今天采到的条目，每条同时显示发布时间与抓取时间；
- **今日缺口**：失败、无新内容、字段异常、凭证缺失，任何启用源「今天没有内容」都必须显式出现；
- **单源诊断**：探活结果、错误、凭证、调度、上次成功时间；
- 数据源清单、启用状态、协议、许可、cron、下次执行；
- 每个启用源的样本内容（V1 复用 3 条/源，目标 10–20 条）。

全库阅览设计见 §3.9：在独立入口查询完整语料、阅读已有正文并查看结构化数据和版本来源；先验证本地只读服务，再评估远端接入。它与日报的抽样数量、生成时间和运行诊断分别表述。

站点通过 **Authentik forward_auth** 登录，不使用 GitHub Pages，不向公网匿名开放。

### 非目标

- 不替代 data-platform 的管理 API；
- 不做采集触发（生成任务由服务器 cron/手动脚本执行）；
- 不做实时监控或盘中多次采集；「今天」指最近一次成功生成；
- 不做角色化双 UI（单用户在同一页面使用「今日体检 / 今日内容」两个镜头）；
- 报表样本页不展开全库正文或原始 JSON；阅览入口按需提供内容与字段，任何界面均不展示凭证；
- 不依赖 farview 主站（Next.js）部署；主站上线后仍可复用本方案。

## 2. 架构

```text
浏览器
  │  https://report.farview.cn
  ▼
openhands-caddy（80/443）
  │  forward_auth → authentik-server 172.17.0.1:9000
  │  file_server → /data/farview-report（Caddy 容器内 caddy-data 卷）
  ▼
index.html + assets/* + report.json

每日 cron / 手动
  ▼
docker run farview-report（Node 20 + data-platform）
  │  config/sources.yml + .env.report
  │  probe + sample fetch（每源 3 条）
  ▼
PostgreSQL 报表读模型（DATA_PLATFORM_DATABASE_URL）
  │  report_runs / report_sources / report_items
  │  SQL 筛选、排序、分页 → CLI / 静态导出
  ▼
caddy-data 卷 /data/farview-report/report.json（原子替换）
/home/ubuntu/work/projects/farview-report/cache/report.json（上次成功样本）
```

**关键决策：**

| 决策 | 结果 |
|------|------|
| 站点形态 | 独立子域名 `report.farview.cn`，不与 `farview.cn` 占位页耦合 |
| 鉴权 | Caddy + Authentik forward_auth；应用/组在 Authentik 后台配置 |
| 数据来源 | 运行报表使用独立探活/抽样读模型；全库阅览直接查询完整语料的目录与正文读模型，两者不混报数量 |
| 更新方式 | 每日 cron + 手动 `run-report.sh`；失败保留上次成功样本；`pnpm report --from-db` 仅重新导出 |
| 开发顺序 | 数据语义与 SQL 查询 → CLI 列表/详情/JSON → Web 渲染；排序规则不写在浏览器中 |
| 页面形态 | 运维报表静态导出；全库阅览使用动态只读查询与紧凑分栏，复用原生 JS/CSS 和视觉规范 |
| 代码同步 | 服务器 `git clone` data-platform 仓库；`update-report.sh` 拉取并重建镜像 |
| GitHub | 不再使用 GitHub Pages / Pages artifact |

## 3. 页面设计

### 3.1 设计前提与主旨

当前阶段报表站点只有一类使用者：一人同时承担运营与运维。因此不按角色拆两套 UI，而是在同一页面提供两个镜头：

- **今日体检**：判断今天的功能是否正确；
- **今日内容**：直接浏览今天采到的内容。

页面主旨：

> 打开页面 30 秒内，判断今天的采集是否可信；然后直接浏览今天采到的内容。

时间口径：**「今天」指最近一次成功生成**。当前是日报节奏（每日 cron + 手动生成），不做实时监控，也不做盘中多次采集。

两个镜头共享同一份「今日采集结果」，区别只是看「有没有问题」还是看「采到了什么」。「今日内容」默认以内容流呈现；需要逐源核对时切到「按源看」，它是同一镜头的核对模式，不是第三个产品。

### 3.2 信息架构

```text
Header：望野 · 今日采集 | 环境 | 生成时间
今日体检：结论 + 运行信息 + 六项检查（调度/覆盖/采集/字段/新鲜/配置）
今日缺口：失败 / 无新内容 / 字段异常 / 凭证缺失；每条可进入单源详情
视图切换：内容流（默认） | 按源看
内容流：筛选（行业/类型/源/搜索）+ 按类型分组 + 条目卡（发布时间 + 抓取时间）
按源看：紧凑表格（状态/今日条数/最新内容/抓取时间/连续失败/耗时/原因）
单源详情：今日样本 + 诊断信息 + 上次成功 + 运行历史（后续）
Footer：生成命令 / report.json / API 索引 / 样本 NDJSON
```

设计约束：

1. **结论先于清单**：首屏先给「今天是否正常」，再给明细；
2. **缺口必须可见**：任何启用源「今天没有内容」都要出现在缺口区，不能被内容流隐藏；
3. **内容优先于源卡片**：默认视图是今天的内容流，不是按源展开的卡片墙；
4. **源表格是核对工具**：需要逐源排查时使用，不占用默认首屏；
5. **单源详情是证据页**：从缺口、内容条目、源表格都能进入同一页。

**为什么保留每源一个详情页**：BEA、Eurostat、IMF、ECB 等源的原始样本链接是 API
（BEA 的 `GetData` URL 还带 `UserID`），直接点开是 JSON。报表把样本标题统一指向
站内详情页，API URL 不再作为可点击链接暴露。

#### 3.2.1 源时效排列与 CLI 优先

本节是 REP-7 / REP-8 的时效浏览设计；完整双镜头目标仍见上文，实施范围见进度真源 §4.12。

- 默认按「近期内容 → 周期数据 → 较旧内容 → 时间待确认 → 暂无可用内容 → 未启用」排列；同组按有效内容时间、近期样本比例、缓存状态、源 ID 稳定排序。
- 发布时间、源更新时间、统计参考周期、抓取成功时间分别保留；参考周期和未来日期不进入全局内容时间排序。年/月日期保留精度，异常日期不推断成当天。
- 论文/专利/试验以近月为浏览窗口，代码/社区/视频以近周为窗口，行情以近期交易数据为窗口；这些是浏览优先级，不是源停更或统计数据过期的判断。
- OpenAlex、Crossref、PubMed、arXiv、ClinicalTrials、YouTube 提供显式近期查询；近期结果为空后使用标明范围的历史查询。其他源保留原采样策略，指标优先 collect。
- 样本变化按稳定标识和有效字段比较，忽略抓取时间与返回顺序；首次观察、采样范围改变时建立基线；缓存/失败/部分结果不推进变化时间，也不冒充新内容。
- 原始记录 ID 优先作为样本标识；旧指标样本结合指标、地区、周期区分，避免共用官方页面链接时合并不同观测值。
- 异常汇总保持在筛选区上方；源后置不隐藏故障。卡片直接显示最新内容、数据周期、抓取成功、缓存和观察说明，无折叠。

数据库查询入口：`src/report/queries.ts`；`queryReportSources` / `queryReportItems` 共用筛选和分页，排序在 SQL 中执行。`loadStoredReport` 固定快照 ID，提供源对象及 `sourceOrders.{recent,name,issues}`，Web 仅按 ID 序列呈现。

```bash
pnpm cli report import --file reports/report.json
pnpm cli report sources --order recent --limit 20
pnpm cli report sources --kind paper --industry 医疗 --json
pnpm cli report items --source openalex --limit 20 --json
pnpm cli report show --source worldbank
pnpm cli report export --out /tmp/farview-report-preview
```

直接 SQL 可查询 `report_latest_sources`；排序列由视图统一提供：

```sql
SELECT source_id, freshness_group, content_at, sample_count
FROM report_latest_sources
ORDER BY freshness_rank, content_at DESC NULLS LAST,
  recent_items::float / NULLIF(sample_count, 0) DESC NULLS LAST,
  stale, source_id COLLATE "C";
```

`report_runs` 保存不可变快照；重复导入同一生成时间保持幂等。导入和历史比较在同一事务中完成；CLI/导出不触发外部采集。发布新生成器前须应用 `038_report_read_model.sql`，并在 `.env.report` 配置可达的独立数据平台库。

### 3.3 功能正确性判定

#### 3.3.1 六项体检

| 检查 | 回答的问题 | 通过标准 |
|------|------------|----------|
| 调度 | 今天按计划跑了吗？跑完了吗？ | 有本次运行记录、正常结束、耗时在预期内 |
| 覆盖 | 所有启用源都尝试了吗？ | 尝试数 = 启用数；未尝试的有明确原因 |
| 采集 | 每个尝试的源都拿到内容了吗？ | 返回 ≥1 条，或属于「该源本就没有新内容」 |
| 字段 | 内容结构对吗？ | 标题/日期/链接/关键字段齐全，无乱码、无重复 |
| 新鲜 | 内容是今天的吗？缓存冒充新数据了吗？ | 抓取时间是今天；内容日期在该类型预期窗口内 |
| 配置 | 凭证、虚拟源、行业标签对吗？ | 必需凭证已配置；禁用源符合预期 |

V1 先用现有 `report.json` 可计算的生成时间/耗时、启用与尝试、样本成功、凭证、抓取时间做初版体检；字段完整性与逐源基线依赖 REP-8 的条目级数据。

#### 3.3.2 单源状态

| 状态 | 含义 | 处理方式 |
|------|------|----------|
| 正常 | 有内容、字段完整、日期新鲜 | 不用管 |
| 正常但无新内容 | 跑通了，但今天没有新条目（低频源可能正常） | 看一眼，确认符合预期 |
| 数据可疑 | 有内容，但字段缺失/日期过旧/重复 | 需要抽查 |
| 采集失败 | 请求失败、超时、限流、接口变更 | 需要处理 |
| 未配置 | 缺凭证，已知缺口 | 不是今天的故障 |
| 未启用 | 配置里关闭 | 不用管 |

#### 3.3.3 运行健康 × 数据可用

| | 数据可用 | 数据不可用 |
|---|---|---|
| 运行健康 | 理想状态 | **静默失败**：探活正常，但样本为空/过期/字段缺失 |
| 运行异常 | **降级可用**：今天失败，但有上次成功的数据 | 双重故障 |

「探活正常」不等于「数据可用」。页面必须同时展示两个轴，避免绿色掩盖「0 条内容」。

#### 3.3.4 正确性基线

每个源需要自己的预期，不能只用全局「0 条 = 失败」：

- 最少条数（`minItems`）；
- 内容最大年龄（`maxAgeDays`，按类型配置）；
- 必备字段（标题、日期、链接、行业等）；
- 上次成功时间与连续失败次数。

没有基线时，「无新内容」只能靠人记忆；有基线后，页面才能判断「偏离该源常态」。

### 3.4 浏览视图

#### 3.4.1 今日内容流（默认视图）

每条内容展示：

- 来源（源名 + 类型）；
- 标题；
- **两个时间**：发布时间、抓取时间；
- 两行摘要；
- 关键字段（作者/国家/数值/公开号等，按类型）；
- 官方页面链接；
- 源详情入口。

两个时间分别回答：

- 抓取时间：这是今天采的吗？
- 发布时间：内容本身新不新？

分组与筛选：

- 默认按类型分组：论文 / 指标 / 专利 / 临床试验 / 社区 / 行情 / 其他；
- 组内按发布时间倒序，提供「最新采集 / 最新发布」切换；
- 筛选：行业、类型、源、是否有日期、搜索；
- 每源目标展示 10–20 条；V1 先复用现有 3 条/源，REP-8 再扩量；
- 今日缺口固定显示在内容流上方。

#### 3.4.2 按源看（核对视图）

紧凑表格，建议列：

`源 / 今日状态 / 今日条数 / 最新内容日期 / 抓取时间 / 连续失败 / 耗时 / 一句话原因`

点行进入单源详情：今日样本 + 诊断信息 + 上次成功 + 运行历史（后续）。

#### 3.4.3 单源详情

- 今日样本（按类型渲染，指标为表格）；
- 诊断：探活结果、错误、凭证、调度、上次成功、连续失败；
- 数据说明：Connector、许可、行业、协议；
- 相关入口：本源 JSON、report.json、API 索引。

### 3.5 按源类型展示

| 类型 | 代表源 | 样本字段 | 新鲜度预期（建议初始值） |
|------|--------|----------|--------------------------|
| 论文 | OpenAlex、CrossRef、PubMed、arXiv、bioRxiv、medRxiv、CORE、Semantic Scholar、OpenCitations | 标题、作者、期刊/日期、摘要片段、DOI/链接 | 30 天 |
| 专利 | PatentsView、EPO、WIPO、Google Patents | 标题、申请人、公开号、日期、链接 | 30 天 |
| 指标 | WorldBank、Eurostat、OECD、IMF、ECB、Census、BEA、FAOSTAT、FRED、EIA | 指标名、国家/地区、周期、数值、单位 | 最新周期 |
| 临床试验 | ClinicalTrials | 标题、状态、phase、适应症、申办方 | 30 天 |
| 社区/代码 | GitHub、Hacker News、Reddit、YouTube | 标题、作者/频道、分数/播放量、日期 | 3 天 |
| 化合物/材料 | ChEMBL、PubChem、Materials Project | 名称/分子式、关键属性、链接 | 不设硬窗口 |
| 行情 | Yahoo Finance | 代码、价格、涨跌幅、时间 | 1 天 |
| 通用 | 其他 | `rawJson` 中最多 4 个标量字段 | 按源配置 |

只保留标题、链接、短摘要（≤300 字符）与关键字段，不落全文/原始 JSON。新鲜度预期为产品初始值，可在源配置中覆盖。

### 3.7 脚本可读接口

生成器在静态站内额外产出只读 JSON/NDJSON，与页面同受 Authentik 保护：

| 路径 | 内容 |
|------|------|
| `/report.json` | 完整 `ReportDocument`（V1 schema 1，目标 schema 2） |
| `/api/v1/index.json` | 生成时间、summary、warnings、源摘要（含 `articleUrl` / `selfUrl`） |
| `/api/v1/sources/<id>.json` | 单源完整对象 + `links.{articleUrl,selfUrl,reportUrl}` |
| `/api/v1/samples.ndjson` | 每行一个样本条目，含 `sourceId` / `kind` / `fields`，便于 `jq` / 流式脚本 |

V1 复用上述接口，不新增「今日」专用 API。若条目量增大到需要跨源分页，再评估 `/api/v1/today.json`，并同步 [数据平台API协议](../knowledge/数据平台API协议.md)。

### 3.8 UI 技术

- `report-ui/index.html`：静态壳，外链 `/assets/styles.css`、`/assets/app.js`；
- `report-ui/assets/app.js`：加载 `report.json`，负责视图切换、筛选、体检结论；
- `report-ui/assets/time.js`：时间标签与观察说明；不计算时效等级或源排名；
- `report-ui/assets/render.js`：体检、缺口、内容流、源表格、单源卡片的渲染；
- `report-ui/assets/article.css`：单源详情排版（指标表格、事实清单、打印样式）；
- `report-ui/assets/styles.css`：farview 设计 token（paper/ink/accent/gold），无外部字体/CDN；
- 无内联脚本；CSP `script-src 'self'`；
- 登录过期时 fetch 会被 Authentik 重定向到 HTML，前端提示「登录已过期，请刷新」。

不引入前端框架，不做角色路由；新增/重写文件 ≤200 行，按渲染职责拆分。

### 3.9 全库阅览与紧凑布局（提案）

目标是“找到任意已入库记录，并在保留列表上下文的情况下连续阅读”。完整指所有记录均可检索、筛选和分页访问，不承诺上游没有提供的全文。数据覆盖、实施范围与验收见[实施进度 §4.12](./实施进度总览.md#412-数据报表站点reportfarviewcn--rep-轨)，恢复快照见[§4.13.3](./实施进度总览.md#4133-新库历史合并)，命令与运行步骤见[阅览手册](../library-reader.md)。本节保留设计依据及后续增强目标，不承担运行状态记录。

**[问题 1] 样本卡片不能承担全量阅览**

严重程度 / Severity: 🟡 Warning

固定每源样本上限会让大量已有记录无法访问；卡片反复展示源说明、协议、状态，也会挤占标题和正文空间。

**修复 / Fix:** 增加独立“阅览”入口，以完整目录查询作为主列表；“数据源”用于选择范围，“运行报表”保留体检用途。主阅览页采用三栏，首屏不放大幅标题、KPI 卡片墙或整段源介绍。

```text
顶栏：阅览 / 数据源 / 运行报表                 数据集与统计时点
工具栏：关键词 | 搜索范围 | 时间 | 内容状态 | 排序 | 布局密度
左栏：类型、源导航 | 中栏：记录列表                   | 右栏：选中记录
源名、数量、最近采集 | 标题 / 源 / 内容时间 / 采集时间 | 正文 / 字段 / 来源与版本
历史源仍可选择     | 上一批 / 下一批 / 当前筛选        | 完整标题、摘要、正文或数据
```

- 桌面以 1440×900 为布局验收基准：左栏约 192–208px，中栏与阅读栏可拖动分配；阅读栏约占剩余宽度四成至一半，可展开为专注阅读。
- 紧凑模式采用约 36px 的单行记录；舒适模式约 48px，显示第二行摘要。列表文字约 14px，正文约 16px；通过减少重复块与间距提高密度，不靠缩小正文。桌面首屏目标约 20 条记录，最终以真实浏览器视口验证。
- 左栏类型与源支持单选/多选，源名旁显示记录数和最近采集时间；默认显示有内容的源，空源可切换查看。支持最近采集、最新内容、数量和名称排序；未知内容时间不伪装成最近更新。
- 大源不使用轮流抽样来冒充完整分页；同一筛选下顺序严格一致。用户可直接选择小源或类型，指标还可切换序列视图，避免大批观测值占满文章列表。
- 选中行在右栏打开，列表保留位置；上下键移动选中项，Enter 进入阅读区，Esc 返回列表或退出专注阅读。搜索输入时不拦截文字按键，所有操作也能通过正常 Tab 和按钮完成。
- 中等宽度折叠源导航，保留列表与正文；小屏切换为“列表 → 阅读 → 返回原位置”，不用把三栏挤到同一屏。触控目标按可操作尺寸验证。
- 筛选、排序、选中记录与数据集身份进入 URL；浏览器前进/后退恢复状态。没有更多结果、没有匹配内容、加载失败分别呈现，失败重试不清空已有列表。

**[问题 2] 异构记录与不同时间被统一当成文章**

严重程度 / Severity: 🟡 Warning

统计观测值、蛋白条目、论文、试验和外链讨论的阅读方式不同。标题可能是数组，日期可能只有年份，正文也可能只存在于旧版本。将所有条目强制渲染成标题加摘要，会出现大块空白和错误的新鲜度判断。

**修复 / Fix:** 列表共享查找与定位方式，阅读栏按类型适配；有多少原始内容就展示多少，不自动补写摘要，也不在打开记录时触发外部抓取。

- 文献/专利：标题、作者或申请人、标识符、发布日期；有摘要先展示摘要，有正文再展开正文，外部原文入口始终明确。
- 指标：默认展示指标、地区、参考周期、数值、单位；序列键包含指标及除时间外的全部维度，避免混合不同性别、年龄、频率或单位。序列页提供完整观测表，再按需要绘制时序；原始记录模式仍可逐条访问。
- 社区/视频：标题、发布时间、评分/评论等已有字段、摘要或站外链接；不将外链记录标成全文采集失败。
- 生物/材料、临床试验：按实体字段分组展示，如物种、条目标识、序列长度，或阶段、疾病与试验标识；不沿用把这些来源都归为论文的旧视图分类。
- 未识别类型也能进入通用字段视图，不能从目录中消失。
- 内容状态区分“全文 / 摘要 / 元数据 / 结构化数据”；支持按正文可用性筛选。没有文档行业标签时提供“未标注”，源的行业配置另称“源分类”，不伪造成文档标签。
- 内容发布时间、采集时间、统计参考周期分别显示；年/月保留其精度，不补成某个具体日。快照统计只描述该快照的内容，不用历史报表状态宣称数据源目前健康。
- 阅读栏保留“正文 / 字段 / 来源与版本”。旧版本补充正文标明原采集时间与来源；不同内容版本优先展示，同内容的多次观察可汇总展开，但不删除底层观察。
- 正文净化后渲染，上游 HTML/XML 和搜索高亮不能直接作为可信 HTML；原始 JSON 按需查看，显示预览时明确标注截断，并提供完整数据下载。

**[问题 3] 全库翻页和检索会放大查询成本**

严重程度 / Severity: 🟡 Warning

按源可查询不等于全库首页足够快；深 OFFSET、每次完整计数、排序时解析大 JSON，都会增加交互等待。现有原始字段英文索引也不能等同于正文检索或全库语义检索。

**修复 / Fix:** 目录投影、候选正文、索引与游标规则归[主设计 §2.4.6](../design.md#246-阅览服务与可重建查询投影)。列表默认按原始采集时间排序，内容时间排序只使用验证过的规范化字段；每批建议 50 条、可选 100 条，用下一批游标继续访问，无每源固定样本总上限。

- 普通目录先完成来源/类型/时间筛选和标识符精确定位；标题、摘要/正文、原始字段的搜索范围明确区分。原始字段检索可以先复用已有能力，正文模式须覆盖历史补充内容后才声称可用。
- 中文与跨语言检索单独验证能力；尚无覆盖的模式不作为默认承诺。相关度排序需评估匹配集合上的计算成本，不能隐藏地把结果截成固定 Top N 后冒充完整匹配分页。
- 列表响应只含轻量展示字段，正文、版本和大 JSON 延迟加载；快速连续切换时取消过期请求，防止旧响应覆盖新选中项。
- 默认返回“是否还有下一批”，总量按统计时点或按需计算；不要为展示“共多少页”阻塞每次搜索。按日期或标识符定位替代超深页码跳转，前端仅保留有限的已加载页面。

**[问题 4] 阅览入口与采集启动耦合**

严重程度 / Severity: 🟡 Warning

给已有采集服务换成恢复库连接，可能使配置同步和调度写入该库；将页面排序另写在浏览器里，又会让 CLI、网页和 SQL 得到不同结果。

**修复 / Fix:** SQL 查询语义与 CLI 先落地，再以独立只读 API 暴露同一查询服务。阅览角色仅有 SELECT，独立进程不启动调度或维护任务，不注册采集/清理管理接口；UI 不直接连接 PostgreSQL，也不提交任意 SQL。鉴权沿用既有边界，运行数据库连接与凭证不进入浏览器。

共享能力由 `library list/show/search`、源目录、正文与版本、指标序列构成；实际路径与参数见[HTTP 契约 §0.7](../knowledge/数据平台API协议.md#07-全库阅览只读服务)。先让全库目录、类型兜底、选中阅读和来源可用，再补深层指标交互、版本比较与检索增强；每轮都以真实数据验证，不能只用少量示例卡片验收。

验收目标：任意源均可继续分页；同时间戳跨批无重复遗漏，未知日期也能到达；CLI 与 HTTP 使用相同筛选、顺序及游标；旧全文可见且来源可追溯；数据与快照版本不混淆；阅览流量不造成业务写入。初版性能目标为常用首屏约 2 秒内、热缓存普通翻页约 500ms 内，全文检索和冷缓存分别实测，不把目标当作既有结果。

评估总结：

| 约束 | 严重度 | 对应方案 |
|------|--------|----------|
| 样本上限与卡片占屏 | Warning | 全量目录、紧凑三栏与连续分页 |
| 类型、时间与正文状态混用 | Warning | 类型适配、精度标记与正文来源 |
| 全库分页和检索成本 | Warning | 轻量投影、索引、游标及延迟加载 |
| 读取与调度、各端排序耦合 | Warning | 独立只读进程、共享 SQL 与 CLI |

## 4. 生成流程

```text
buildScheduleReport + attachNextRunTimes   → 源矩阵
probeExternalSourceDetailed                → 探活（按 base connector 缓存）
指标类源 → connector.collect({ maxItems: 3 })  → 带数值/单位/周期
支持近期查询的源 → 带窗口与时间倒序的 search → 空结果回退历史 search
其他源   → connector.search(query, 3) → 空结果再 collect
凭证缺失 / 禁用 / 无 Connector              → 跳过并记录原因
上次成功样本 + 本次失败                     → stale=true 保留
汇总 summary / warnings → saveReport（事务入库 + 观察历史）
数据库 SQL 查询 → loadStoredReport → HTML / JSON / NDJSON（同一快照）
```

- **query 优先级**：虚拟源 `schedule_query` → `options.default_collect_query` → 每源兜底 query。
- **并发**：4；单源超时 8–10 秒；单源失败不阻塞整页。
- **脱敏**：URL 与错误信息移除 `api_key`/`token`/`Authorization`/`UserID`；API URL 不作为样本外链。
- **缓存**：`/cache/report.json` 保存上次成功样本；容器重启/单源失败不影响已展示内容。
- **详情页/接口**：CLI 与生成器共用 `src/report/writeReport.ts`；`pnpm report --from-db` 不请求外部数据源。
- **环境**：`NODE_ENV=production`；生成/导出需要现有 `DATA_PLATFORM_DATABASE_URL`，禁止回退父仓 `DATABASE_URL`。
- **目标（REP-8）**：在现有流程上补 run 摘要（started/finished/attempted/completed/cache）、条目级 `fetchedAt`、每源 `expected` 基线与 `fieldIssues`，并生成单源 `status` 六分类；V1 先用现有字段做初版体检。


### 5.6 登录后 404 排障

按顺序检查：

1. **Caddy 容器内是否有文件**：
   ```bash
   docker exec openhands-caddy ls -lh /data/farview-report
   ```
   应看到 `index.html`、`report.json`、`assets/`。
2. **Caddy root 是否指向卷内路径**：
   ```bash
   docker exec openhands-caddy grep 'root \* /data/farview-report' /etc/caddy/Caddyfile
   ```
3. **宿主机改了但容器没变**：Caddyfile 是单文件 bind mount，`sed -i` 会替换 inode，`caddy reload` 仍读旧文件。此时必须：
   ```bash
   docker restart openhands-caddy
   ```
4. 未登录 `curl -sSI https://report.farview.cn/` 应 302 到 `auth.farview.cn`；登录后应 200。
5. 仍 404 时看 `/data/access-report.log`：`Server: Caddy` 且 `size:0` 通常是静态文件未命中；`X-Authentik-Id` 存在则是 Authentik 侧返回。

## 6. 安全

- 全站 Authentik forward_auth；`report.json` 与静态资源同样受保护；
- `.env.report` 仅服务器本地、`chmod 600`，不进入镜像/仓库/HTML；
- 只展示 env 名称与 configured/missing，不展示值；
- URL/错误脱敏（含 BEA `UserID`）；API URL 不作为样本外链，旧缓存读入时同样剔除；
- 指标类样本优先 `collect`，文章页直接展示数值/单位/周期，而非原始 JSON；
- 不落全文；`X-Robots-Tag noindex`；文章页/接口同样经 Authentik；
- `Cache-Control: no-store`（HTML/JSON）；
- 容器：非 root、`--read-only`、`--tmpfs /tmp`、`--cap-drop ALL`、不挂 Docker socket；
- 服务器位于国内，部分源可能需要出站代理；先直连，失败在页面显示原因；
- 报表生成日志按天切割，不记录 Key。

| REP-4 | Caddy + Authentik + DNS | `https://report.farview.cn` 登录后可见 |
| REP-5 | 全量源适配 + 文档/验收 | 每个启用源 3 条或明确失败原因 |
| REP-6 | 无折叠源卡片 + 每源文章页 + API v1 | 样本标题进文章页；`/api/v1/*` 可用；BEA 无 `UserID` 外链 |
| REP-7 | 今日采集浏览界面 V1（体检+缺口+内容流+按源看+单源详情） | 首屏 30 秒结论；缺口不隐藏；内容流可筛选；源表格可定位异常 |
| REP-8 | 正确性基线 + 条目级数据（`fetchedAt` / 10–20 条 / 字段完整性 / 连续失败） | 静默失败可见；基线可配置；六项体检完整 |

**MVP 范围**：REP-1～REP-4 + 已配置凭证的源全部尝试；未配置凭证的源显示原因。

**当前 UI 改版**：REP-7（今日采集 V1）→ REP-8（正确性基线）；设计见 §3。

**全量**：REP-5 补齐高风险源（WIPO/EPO/Google Patents 等）与运维文档。

## 8. 验收方法

> 当前状态 → [实施进度总览 §4.12](./实施进度总览.md)。

- `pnpm build` / `pnpm test:run` 通过；
- `node --import tsx scripts/generate-report.mjs --out reports` 生成 `report.json`；
- `report.json` 中无 `api_key`/`Bearer`/`UserID`/Key 值；
- 每个启用源有样本（V1 3 条，目标 10–20 条）或明确 `sample.error`；
- 指标源样本含数值/单位/周期；`/sources/<id>.html` 直接可读，指标渲染为表格；
- `/api/v1/index.json`、`/api/v1/sources/<id>.json`、`/api/v1/samples.ndjson` 返回 200；
- 未登录访问 `report.farview.cn` 跳转 Authentik；
- 首屏 30 秒内能判断「今天是否正常、哪里不正常」；
- 今日缺口列出所有启用但无内容的源，不能静默隐藏；
- 内容流可按类型/行业/源筛选，条目显示发布时间与抓取时间；
- 按源看表格能定位异常源并进入单源详情；
- 六项体检与单源状态分类一致；「探活正常但 0 条内容」显示为静默失败；
- 登录后页面正常渲染、筛选可用；
- 生成失败时保留上次 `report.json`；
- Caddy `validate`/`reload` 通过；
- cron 每日执行、日志可查。
