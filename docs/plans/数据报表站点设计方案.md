## 1. 目标与范围

在 `tx-cloud` 上部署 **`https://report.farview.cn`**，展示 data-platform 的：

- 数据源清单、启用状态、协议、许可、cron、下次执行；
- 探活结果（HTTP 状态、耗时、失败原因、凭证是否配置）；
- **每个已启用源 3 条样本内容**（标题、链接、日期、短摘要、类型化字段）；
- 凭证缺口、无 Connector、样本失败/过期等运维告警。

站点通过 **Authentik forward_auth** 登录，不使用 GitHub Pages，不向公网匿名开放。

### 非目标

- 不替代 data-platform 的管理 API；
- 不做采集触发（生成任务由服务器 cron/手动脚本执行）；
- 不展示全文、原始 JSON 或任何 API Key；
- 不依赖 farview 主站（Next.js）部署；主站上线后仍可复用本方案。

## 2. 架构

```text
浏览器
  │  https://report.farview.cn
  ▼
openhands-caddy（80/443）
  │  forward_auth → authentik-server 172.17.0.1:9000
  │  file_server → /home/ubuntu/work/projects/farview-report/data
  ▼
index.html + assets/* + report.json

每日 cron / 手动
  ▼
docker run farview-report（Node 20 + data-platform）
  │  config/sources.yml + .env.report
  │  probe + sample fetch（每源 3 条）
  ▼
/home/ubuntu/work/projects/farview-report/data/report.json（原子替换）
/home/ubuntu/work/projects/farview-report/cache/report.json（上次成功样本）
```

**关键决策：**

| 决策 | 结果 |
|------|------|
| 站点形态 | 独立子域名 `report.farview.cn`，不与 `farview.cn` 占位页耦合 |
| 鉴权 | Caddy + Authentik forward_auth；应用/组在 Authentik 后台配置 |
| 数据来源 | 服务器本地生成，直连各数据源；不回传第三方公开页面 |
| 更新方式 | 每日 cron + 手动 `run-report.sh`；失败保留上次成功样本 |
| 页面形态 | 静态 `index.html` + 原生 JS + CSS，无前端框架 |
| 代码同步 | 服务器 `git clone` data-platform 仓库；`update-report.sh` 拉取并重建镜像 |
| GitHub | 不再使用 GitHub Pages / Pages artifact |

## 3. 页面设计

### 3.1 信息架构

```text
Header：望野 · 数据采集报表 | 环境 | 生成时间 | 文档
KPI：源总数 / 启用 / Connector / 健康 / 降级 / 失败 / 样本成功 / 凭证缺口
需要关注：无 Connector、凭证缺失、探活失败、样本失败/过期
筛选：搜索 / 状态 / 行业 / 协议 / 只看有样本
数据源卡片（可展开）：
  源名 + id + 虚拟标记
  状态 pill / 行业 / 协议 / 最近样本 / 凭证 / cron
  展开：3 条样本卡片 + 探活详情 + 许可/商用/调度
Footer：生成命令、data-platform 版本、设计文档链接
```

### 3.2 按源类型展示

| 类型 | 代表源 | 样本字段 |
|------|--------|----------|
| 论文 | OpenAlex、CrossRef、PubMed、arXiv、bioRxiv、medRxiv、CORE、Semantic Scholar、OpenCitations | 标题、作者、期刊/日期、摘要片段、DOI/链接 |
| 专利 | PatentsView、EPO、WIPO、Google Patents | 标题、申请人、公开号、日期、链接 |
| 指标 | WorldBank、Eurostat、OECD、IMF、ECB、Census、BEA、FAOSTAT、FRED、EIA | 指标名、国家/地区、周期、数值、单位 |
| 临床试验 | ClinicalTrials | 标题、状态、phase、适应症、申办方 |
| 社区/代码 | GitHub、Hacker News、Reddit、YouTube | 标题、作者/频道、分数/播放量、日期 |
| 化合物/材料 | ChEMBL、PubChem、Materials Project | 名称/分子式、关键属性、链接 |
| 行情 | Yahoo Finance | 代码、价格、涨跌幅、时间 |
| 通用 | 其他 | `rawJson` 中最多 4 个标量字段 |

只保留标题、链接、短摘要（≤300 字符）与关键字段，不落全文/原始 JSON。

### 3.4 UI 技术

- `report-ui/index.html`：静态壳，外链 `/assets/styles.css`、`/assets/app.js`；
- `report-ui/assets/app.js`：`fetch("/report.json")`，原生 JS 渲染筛选/卡片/展开；
- `report-ui/assets/styles.css`：farview 设计 token（paper/ink/accent/gold），无外部字体/CDN；
- 无内联脚本；CSP `script-src 'self'`；
- 登录过期时 fetch 会被 Authentik 重定向到 HTML，前端提示“登录已过期，请刷新”。

## 4. 生成流程

```text
buildScheduleReport + attachNextRunTimes   → 源矩阵
probeExternalSourceDetailed                → 探活（按 base connector 缓存）
connector.search(query, maxResults: 3)     → 样本
  空结果 → connector.collect({ query, maxItems: 3 })
凭证缺失 / 禁用 / 无 Connector              → 跳过并记录原因
上次成功样本 + 本次失败                     → stale=true 保留
汇总 summary / warnings → 原子写 report.json
```

- **query 优先级**：虚拟源 `schedule_query` → `options.default_collect_query` → 每源兜底 query。
- **并发**：4；单源超时 8–10 秒；单源失败不阻塞整页。
- **脱敏**：URL 与错误信息移除 `api_key`/`token`/`Authorization`；凭证只输出 env 名称与 configured。
- **缓存**：`/cache/report.json` 保存上次成功样本；容器重启/单源失败不影响已展示内容。
- **环境**：`NODE_ENV=production`；不新增应用运行时 ENV。

## 5. 部署与鉴权

### 5.1 服务器目录

```text
/home/ubuntu/work/projects/farview-report/
├── data/                    # Caddy 静态根
│   ├── report.json          # 每日生成
│   ├── index.html
│   └── assets/
├── cache/report.json        # 上次成功样本（不对外）
├── .env.report              # chmod 600
├── run-report.sh
└── logs/
```

### 5.2 代码同步与生成

```bash
# 首次
git clone git@github.com:wwhdx/data-platform.git \
  /home/ubuntu/work/projects/data-platform
cd /home/ubuntu/work/projects/data-platform
git checkout feat/report-mvp
docker build -f Dockerfile.report -t farview-report:latest .

# 更新
/home/ubuntu/work/projects/farview-report/update-report.sh
# 手动生成
/home/ubuntu/work/projects/farview-report/run-report.sh
```

Cron（北京时间 12:30，03:00 UTC 采集之后）：

```cron
30 12 * * * /home/ubuntu/work/projects/farview-report/run-report.sh >> /home/ubuntu/work/projects/farview-report/logs/report.log 2>&1
```

### 5.3 Caddy

新增独立站点块（完整片段见 `deploy/report/Caddyfile.snippet`）：

```caddyfile
report.farview.cn {
    import security_headers_deny
    header X-Robots-Tag "noindex, nofollow"
    route {
        reverse_proxy /outpost.goauthentik.io/* http://172.17.0.1:9000
        forward_auth http://172.17.0.1:9000 {
            uri /outpost.goauthentik.io/auth/caddy
            copy_headers X-Authentik-Username X-Authentik-Groups X-Authentik-Email X-Authentik-Name
            trusted_proxies private_ranges
        }
        root * /home/ubuntu/work/projects/farview-report/data
        try_files {path} /index.html
        file_server
    }
}
```

修改后：

```bash
docker exec openhands-caddy caddy validate --config /etc/caddy/Caddyfile
docker exec openhands-caddy caddy reload --config /etc/caddy/Caddyfile
```

### 5.4 Authentik

1. 新建组 `farview-ops`，加入需要查看报表的用户；
2. 新建 Proxy Provider：`report.farview.cn`，Forward auth (single application)；
3. 新建 Application：`望野数据报表`，Provider 指向上述；
4. 将 Provider 加入 Embedded Outpost；
5. 验证：未登录访问 → 跳转 `auth.farview.cn`；登录后 → 报表。

### 5.5 DNS

```text
report.farview.cn  A  <tx-cloud 公网 IP>
```

与 `status.farview.cn` 保持一致；若使用代理/CDN，需保证 Caddy ACME 可完成证书签发。

## 6. 安全

- 全站 Authentik forward_auth；`report.json` 与静态资源同样受保护；
- `.env.report` 仅服务器本地、`chmod 600`，不进入镜像/仓库/HTML；
- 只展示 env 名称与 configured/missing，不展示值；
- URL/错误脱敏；不落全文；`X-Robots-Tag noindex`；
- `Cache-Control: no-store`（HTML/JSON）；
- 容器：非 root、`--read-only`、`--tmpfs /tmp`、`--cap-drop ALL`、不挂 Docker socket；
- 服务器位于国内，部分源可能需要出站代理；先直连，失败在页面显示原因；
- 报表生成日志按天切割，不记录 Key。

## 7. 实施阶段（REP 轨）

| ID | 任务 | 验收 |
|----|------|------|
| REP-1 | 报告 schema + probe/sample/cache/脱敏 | `report.json` 通过 schema/单测；无密钥泄漏 |
| REP-2 | 静态 UI（KPI/筛选/源卡片/3 样本） | 本地 `python3 -m http.server` 可浏览；移动端可用 |
| REP-3 | Dockerfile.report + 服务器部署脚本 | 服务器 `docker run` 生成 `report.json` |
| REP-4 | Caddy + Authentik + DNS | `https://report.farview.cn` 登录后可见 |
| REP-5 | 全量源适配 + 文档/验收 | 每个启用源 3 条或明确失败原因 |

**MVP 范围**：REP-1～REP-4 + 已配置凭证的源全部尝试；未配置凭证的源显示原因。  
**全量**：REP-5 补齐高风险源（WIPO/EPO/Google Patents 等）与运维文档。

## 8. 验收方法

> 当前状态 → [实施进度总览 §4.12](./实施进度总览.md)。

- `pnpm build` / `pnpm test:run` 通过；
- `node --import tsx scripts/generate-report.mjs --out reports` 生成 `report.json`；
- `report.json` 中无 `api_key`/`Bearer`/Key 值；
- 每个启用源有 3 条样本或明确 `sample.error`；
- 未登录访问 `report.farview.cn` 跳转 Authentik；
- 登录后页面正常渲染、筛选可用；
- 生成失败时保留上次 `report.json`；
- Caddy `validate`/`reload` 通过；
- cron 每日执行、日志可查。
