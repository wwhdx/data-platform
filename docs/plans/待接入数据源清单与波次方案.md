## 1. 目标与范围

### 1.1 目标

在 [波次 0–4](./剩余数据源接入实施方案.md#13-波次-04-完成与后续)（17 个 Connector 已全部落地）基础上，对照 [真实行业获取指南](../knowledge/真实行业获取指南.md) 梳理**下一批可合法接入**的外部数据源，给出优先级、协议映射、**数据形态**、实施波次与 profile/ENV 规划，供排期与 YAML/`interface_profiles` 使用。

### 1.2 非目标

- 不重复维护已实现 Connector 的端点/字段（见 [data-sources.md](../data-sources.md)）
- 不含商业订阅源（Scopus、Crunchbase、Bloomberg 等）的采购谈判
- 不含无官方 API、需爬虫的中国本土源（CNIPA、巨潮、百度指数等）的实施方案——仅登记为「暂缓」
- **per-source 端点与字段真源**：落地时在 `data-sources.md` 开节；本文只写规划级决策

### 1.3 已实现基线（2026-05-20）

| 维度 | 数量 | 真源 |
|------|------|------|
| YAML `sources[]` | 18（含 Legacy `arxiv`） | `config/sources.yml` |
| 运行时 Connector | 17 | `src/connectors/bootstrap.ts` `REGISTERED_CONNECTOR_IDS` |
| 指南 MVP 四件套 | ✅ | OpenAlex + S2 + arXiv + 政府/SEC/专利 |

指南 [§六 启动期路线](../knowledge/真实行业获取指南.md#六给启动期团队的实战路线) 第 2–3 周「免费源」已基本覆盖；本文档聚焦**垂直补洞**与**已有源加深**。

## 3. 待接入清单（按优先级）

> **协议分类** → [免费数据源接口分类分析 §13](../knowledge/免费数据源接口分类分析.md#13-待接入源规划2026-05-20)  
> **行业栈对照** → 本文 §5  
> **数据形态**：`paper_abstract`（向量主路径）· `indicator`（同 `worldbank`/`fred`）· `graph_edge`（引文/实体，检索为辅）· `enrich_metadata`（不单独建库，挂 DOI/已有文档）

### 3.1 P0 — 立即规划（低难度 + 高 RAG 价值 + 开放许可）

| 规划 `id` | 名称 | 协议 / profile | 数据形态 | RAG | 许可 / 备注 |
|-----------|------|----------------|----------|-----|-------------|
| `biorxiv_oai` | bioRxiv | OAI-PMH → `oai_pmh` + **源级 `base_url` 覆盖** | `paper_abstract` | ⭐⭐⭐⭐ | 复用 `arxivOai.ts`；`ListRecords` + 摘要 |
| `medrxiv_oai` | medRxiv | 同上 | `paper_abstract` | ⭐⭐⭐⭐ | 与 bioRxiv 同批；OAI 端点不同于 arXiv |
| `chembl` | ChEMBL | REST → `rest_none` | `paper_abstract` / 结构化分子 | ⭐⭐⭐⭐ | 分子活性；端点见落地时 `data-sources.md` |
| `core` | CORE | REST Key → `rest_query_param_key` | `paper_abstract` | ⭐⭐⭐⭐ | 补 CrossRef 全文缺口；须 attribution（§3.5） |

### 3.2 P1 — 季度内（中等难度 + 行业垂直）

| 规划 `id` | 名称 | 协议 / profile | 数据形态 | RAG | 许可 / 备注 |
|-----------|------|----------------|----------|-----|-------------|
| `pubchem` | PubChem | PUG REST → `rest_none` 或共享 `ncbi_eutils` | 结构化化合物 | ⭐⭐⭐ | 与 `pubmed` 协同 CID/名称映射 |
| `uniprot` | UniProt（可选） | `ncbi_eutils` 或 REST | 结构化蛋白 | ⭐⭐ | 波次 6 可选；非独立 MVP |
| `stackoverflow` | Stack Overflow | Stack Exchange → `rest_query_param_key` | `paper_abstract`（问答正文） | ⭐⭐⭐ | Key + attribution（§3.5） |
| `materials_project` | Materials Project | REST Key → `rest_query_param_key` | 结构化材料 | ⭐⭐⭐ | 制造栈 |
| `eia` | EIA | REST Key → `rest_query_param_key` | `indicator` | ⭐⭐ | 能源宏观 |
| `eurostat` | Eurostat | REST JSON → `rest_none`（或 `sdmx_json`） | `indicator` | ⭐⭐ | 同 `worldbank` 分块策略 |
| `oecd` | OECD | SDMX-JSON → 待 `sdmx_json` profile | `indicator` | ⭐⭐ | 与 `imf` 同类；实现前定 parser |
| `opencitations` | OpenCitations | **Phase-1 REST 子集** → `rest_none`；SPARQL 二期 | `graph_edge` | ⭐⭐ | 增强 OpenAlex/S2；图谱存储见 §4.2 |
| `unpaywall` | Unpaywall | **非新 Connector** | `enrich_metadata` | ⭐ | DOI→OA URL；见 §4 波次 5+ |

### 3.3 P2 — 按需（复杂度或重叠较高）

| 规划 `id` | 名称 | 协议 / profile | 数据形态 | 难点 |
|-----------|------|----------------|----------|------|
| `gdelt` | GDELT | `bigquery_sql`（对齐 `google_patents`） | 事件/新闻摘要 | 须 `GCP_PROJECT_ID` + ADC |
| `wipo` | WIPO PatentScope | **待增** `wipo_ops` 或 REST 子集 | 专利元数据 | 与 `epo_ops`、`google_patents` 重叠 |
| `alpha_vantage` | Alpha Vantage | `rest_query_param_key` | `indicator` | 与 `yahoo_finance` 重叠 |
| `coingecko` | CoinGecko | `rest_none` | `indicator` | 加密货币 niche |
| `opencorporates` | OpenCorporates | REST | 公司注册 | 免费层有限 |
| `google_trends` | Google Trends | 非官方 | `indicator` | 稳定性无保证；运维对齐 `yahoo_finance` |
| `census` / `imf` | Census / IMF | REST / SDMX | `indicator` | 与 World Bank / OECD 同类；**本期无波次** |

### 3.4 P3 — 暂缓（商业 / 合规 / 无 API）

| 类别 | 代表 | 暂缓原因 |
|------|------|----------|
| 机构订阅 | Scopus、WoS、Dimensions、Bloomberg、Nielsen | 无开放 API，成本高 |
| 商业 API | Crunchbase、PitchBook、SimilarWeb、Statista | 付费 + 许可谈判 |
| 中国本土无 API | CNIPA、巨潮、国家统计局、百度指数、小红书、抖音 | 爬虫 + ToS/PIPL 风险 |
| 政策收紧 | X (Twitter) | 商业 API 极贵 |
| 学术限制 | DrugBank | 学术免费 / 商业付费，许可复杂 |
| 机构/付费全文 | **IEEE Xplore**、Lens.org（深度） | 订阅或免费层不足；专利/学术主路径已由现有源覆盖 |
| 重叠且非必要 | Lens.org（检索） | 免费层有限；`google_patents` + `epo_ops` 已覆盖主路径 |

### 3.5 开放 API 合规备忘（实施门闸）

| 源 / 任务 | 要点 |
|-----------|------|
| **CORE** | 注册 API Key；响应须保留 attribution 字段入 `raw_json` |
| **Stack Exchange** | `STACK_EXCHANGE_KEY`（或等价 env）；遵守 [API Terms](https://api.stackexchange.com/docs/terms-of-use) |
| **Reddit 启用** | OAuth 凭证 + `REDDIT_USER_AGENT`；存储政策与 PII 评审后再 `enabled: true` |
| **SEC / arXiv 系** | User-Agent / 礼貌池；SEC 禁止高频裸爬 |
| **非官方**（`google_trends`、`yahoo_finance`） | 仅辅助指标；不承诺 SLA；文档标注「非官方」 |

## 4. 实施波次（5–8）

### 4.0 依赖关系（硬 / 软）

| 前置 | 后置 | 类型 | 说明 |
|------|------|------|------|
| `arxiv_oai` 模板 | `biorxiv_oai` / `medrxiv_oai` | 硬 | 代码复用 + YAML `base_url`  per 源 |
| `crossref` / `openalex`（DOI） | `unpaywall` 富化 | 软 | 建议 processor 批处理，非独立 cron 源 |
| `openalex` / `semanticscholar` | `opencitations` | 软 | 引文增强；可先 REST 边表入 `raw_json` |
| `google_patents` GCP 栈 | `gdelt` | 软 | 共享 `GCP_PROJECT_ID`、ADC 挂载 |
| `pubmed` | `pubchem` / `uniprot` | 软 | 共享 NCBI 限速与 Key 策略 |

### 4.1 波次总览

```
波次 5（学术加深）   bioRxiv + medRxiv → CORE → OpenCitations → Unpaywall 富化
波次 6（医药垂直）   ChEMBL → PubChem →（可选 UniProt）
波次 7（行业扩展）   Materials Project → EIA → Eurostat / OECD
波次 8（舆情补全）   Stack Overflow → Reddit 启用 → GDELT
```

### 4.3 Profile 与基础设施

| 需求 | 动作 | 触发的波次 |

## 6. 验收（三级）

### 6.1 L1 — 单元与类型（每源 / 每项加深）

```bash
pnpm exec tsc --noEmit
pnpm test:run -- src/__tests__/unit/<id>.test.ts
pnpm cli config validate
```

### 6.2 L2 — 采集冒烟（本地，需 Key / 网络；不进 CI）

```bash
pnpm cli collect --source <id> --query "test" --max-items 5
pnpm cli export --source <id>   # 可选 D1 样本
```

| 数据形态 | 额外检查 |
|----------|----------|
| `paper_abstract` | `document_chunks` 非标题-only（[RAG 方案 §7](./数据源接入与RAG构建方案.md)） |
| `indicator` | `chunk.ts` `indicatorChunks`；hybridSearch 可关键词命中 |
| `enrich_metadata` | 已有文档 `raw_json` 出现约定字段（如 `oa_url`） |
| D5 | 导出 `schemaVersion: 2` 含 `provenance`（[原始数据方案 §4.7](./原始数据本地导出与镜像方案.md#47-数据来源溯源provenanced5)） |

### 6.3 L3 — RAG / 集成回归（有摘要源、发版前）

```bash
EMBED_BACKEND=mock pnpm test:integration
# 或 Ollama L2-full：确认 hybridSearch 能命中摘要关键词
```

真源外网脚本（可选）：`scripts/collect-live-<id>.sh`，季度人工跑，与 [剩余方案 §11.2](./剩余数据源接入实施方案.md#112-不进入-ci-的真源脚本l3可选) 一致。
