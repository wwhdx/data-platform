## 1. 策略：子包先行、父仓后接

| 阶段 | 范围 | 验收 |
|------|------|------|
| **Phase 1（本仓库）** | Connector / API / RAG / `DataPlatformClient` / P+I 轨测试 | `pnpm e2e:loop` 绿 |
| **Phase 2（父仓）** | `src/lib/dataPlatform.ts` 薄封装或 workspace 依赖子包 client | 复用 P 轨同一契约 |
| **Phase 3（父仓）** | engine-core `searchProvider` + Admin 页 + 代理路由 | C2→C3→C4 |

**原则**：父仓**不直连** data-platform 数据库；一切经 HTTP。子包在 P 轨用**真 PostgreSQL + 真 Fastify**验证与父仓相同的 fetch 路径。

## 2. 集成点 ↔ API ↔ 测试映射

| 父仓集成点 | HTTP | `DataPlatformClient` | P 轨用例 |
|------------|------|----------------------|----------|
| **A** 文章生成知识注入 | `POST /api/search` | `search()` | `P-A` + I 轨 `SearchProvider` |
| **B** 全局搜索扩展 | `POST /api/search` + filters | `search({ filters })` | `P-B` |
| **C** 行业页富化 | 同 A | `search()` | 与 A 同契约，父仓加行业 query |
| **D** 管理后台监控 | `GET /api/sources` + `GET /api/admin/stats` | `getSources()` / `getStats()` | `P-D` |
| **E** 手动采集 | `POST /api/admin/collect` | `triggerCollect()` | `P-E` |
| **F** 定时调度 | 内部 cron | `getSchedules()` | `P-F` |
| **—** 健康 / 降级 | `GET /health` | `health()` / `isReachable()` | `P-Health` / `P-Graceful` |
| **C3** engine-core | 同上 | `createDataPlatformSearchProvider()` | `P-A` |

## 4. `DataPlatformClient`（C2 子包真源）

**路径**：`src/client/dataPlatformClient.ts`

| 方法 | 说明 | 失败行为 |
|------|------|----------|
| `search(req)` | 知识检索 | `[]` |
| `getSources()` | 数据源列表 | `[]` |
| `getStats()` | 文档/任务统计 | 零值对象 |
| `health()` | 健康 + 逐源探活 | `null` |
| `triggerCollect(opts?)` | 手动采集 | `null` |
| `getJobs(limit?)` | 任务历史 | `[]` |
| `getSchedules()` | live cron | `null` |
| `isReachable()` | 布尔探活 | `false` |
| `static fromEnv()` | 读 `DATA_PLATFORM_URL` | 未设置 → `null` |

父仓 Phase 2 可选：

```typescript
// 方案 A：workspace 依赖（推荐）
import { DataPlatformClient } from "@wangye/data-platform";

// 方案 B：复制 client 文件（不推荐，易漂移）
```

## 7. 与 I 轨分工

| 轨 | 验证重点 | 消费者替身 |
|----|----------|------------|
| **I** | 采集→embed→检索 数据面 | `SearchProvider` only |
| **P** | 父仓全部 HTTP 集成点 | `DataPlatformClient` 全方法 |

I 轨通过即数据管道可用；P 轨通过即**父仓可开干 C2–C4**。
