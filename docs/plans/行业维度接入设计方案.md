## 一、背景与目标

### 1.1 问题

当前 data-platform 是**行业无感知**的通用检索系统：
- 29 个 Connector 按数据源（OpenAlex、PubMed、SEC 等）组织，不区分望野行业 taxonomy
- `/api/search` 返回全库混合结果，无法按行业过滤
- 调度器对所有启用源等频采集，不区分热冷行业

这导致：当 engine-core 生成"医疗行业常青文章"时，搜索结果可能混入无关的金融、能源文档，降低 RAG 检索相关性。

### 1.2 目标

在 **不引入行业数据库耦合** 的前提下，为 data-platform 增加行业维度能力：

| 能力 | 说明 |
|------|------|
| **行业标签存储** | 文档可携带 `industry_tag` 字符串标签 |
| **行业过滤检索** | `/api/search?industry=医疗` 可按行业过滤结果 |
| **Connector 行业预分配** | 各数据源配置默认行业映射，采集时自动打标 |
| **行业同步接口** | 接受主包推送的行业变更，维护本地行业列表 |
| **调度优先级** | 活跃行业数据源可配置更高采集频率 |

### 1.3 非目标

- **不重建行业 ontology**：`SourceCategory` 分类树、图谱重建、孵化申请逻辑仍完全属于主包
- **不验证行业合法性**：标签合法性由主包保证，data-platform 只做存储和过滤
- **不按行业建立独立数据库**：统一在现有 `raw_documents` + `document_chunks` 表扩展字段
- **不主动拉取主包行业列表**：采用主包单向推送，避免逆向轮询依赖

## 二、架构设计

### 2.1 耦合策略：松耦合字符串标签

```
主包（SourceCategory 真源）
  │
  │  行业激活/停用时单向推送
  │  POST /api/admin/industry-tags/sync
  ▼
data-platform（本包）
  ├─ industry_tags 表（本地轻量缓存）
  │   name: string | is_active: bool | activated_at: timestamptz
  │
  ├─ raw_documents.industry_tag?: string  ← 可空，不 FK
  ├─ document_chunks.industry_tag?: string ← 随文档继承
  │
  └─ /api/search?industry=医疗  ← 检索时可选过滤
```

**关键约束**：
- `industry_tag` 是普通字符串列，**不是外键**，不依赖主包 DB schema
- data-platform 不验证标签值，只存储和过滤
- 主包是标签的权威来源，data-platform 仅做 cache

### 2.2 数据流

```
Connector.collect()
    │
    ├─ 静态映射（connector.defaultIndustryTag）────────► raw_documents.industry_tag
    │
    ├─ YAML 源级配置（sources.yml industry_tag 字段）──► raw_documents.industry_tag
    │
    └─ AI 分类（Phase 3，仅通用源无标签时）────────────► raw_documents.industry_tag

raw_documents.industry_tag
    │
    ▼ 处理流水线继承
document_chunks.industry_tag
    │
    ▼ 检索
hybridSearch(query, { industryTag })
    │
    ▼
/api/search 响应（含 industry_tag 字段）
```

## 三、数据模型变更

### 3.1 新增 `industry_tags` 表（迁移 023）

```sql
-- migration 023: add_industry_tags
CREATE TABLE industry_tags (
  name        TEXT        PRIMARY KEY,
  is_active   BOOLEAN     NOT NULL DEFAULT true,
  activated_at TIMESTAMPTZ,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_industry_tags_active ON industry_tags(is_active);
```

**用途**：本地缓存望野激活的行业列表，供调度器查询冷热优先级。

### 3.2 `raw_documents` 表增加 `industry_tag` 列（迁移 024）

```sql
-- migration 024: add_industry_tag_to_documents
ALTER TABLE raw_documents ADD COLUMN industry_tag TEXT;
ALTER TABLE document_chunks ADD COLUMN industry_tag TEXT;

CREATE INDEX idx_raw_docs_industry ON raw_documents(industry_tag) WHERE industry_tag IS NOT NULL;
CREATE INDEX idx_chunks_industry ON document_chunks(industry_tag) WHERE industry_tag IS NOT NULL;
```

**说明**：
- 可空（`NULL` = 未分类），不影响现有数据
- 不设外键约束，允许独立运作
- 现有文档迁移后 `industry_tag = NULL`，不强制回填

## 四、Connector 行业预分配

### 4.1 静态映射表（connector 配置）

大多数数据源天然对应特定行业，在 `BaseConnector` 层增加 `defaultIndustryTag` 可选字段：

```typescript
// src/connectors/base.ts
export abstract class BaseConnector {
  readonly defaultIndustryTag?: string;  // 新增可选字段
  // ...
}
```

各 Connector 典型映射（可覆盖）：

| Connector | 推荐 `defaultIndustryTag` | 说明 |
|-----------|--------------------------|------|
| `pubmed` | `医疗` | PubMed 生物医学论文 |
| `clinicaltrials` | `医疗` | 临床试验数据库 |
| `chembl` | `医疗` | 化学生物数据库 |
| `sec_edgar` | `金融` | SEC 财务报告（可按 SIC 码细分） |
| `fred` | `金融` | 美联储经济数据 |
| `yahoo_finance` | `金融` | 股票/市值数据 |
| `eia` | `能源` | 美国能源信息署 |
| `patentsview` | `科技` | 专利数据库 |
| `github` | `科技` | 开源项目 |
| `openalex` | `NULL` | 全学科，不预分配 |
| `crossref` | `NULL` | 全学科，不预分配 |
| `arxiv_oai` | `NULL` | 全学科，不预分配 |
| `worldbank` | `NULL` | 宏观经济，跨行业 |

### 4.2 YAML 源级配置（`sources.yml` 扩展）

允许在 `sources.yml` 的单个源实例上覆盖行业标签：

```yaml
# config/sources.yml 扩展示例
sources:
  - id: openalex_medical
    connector: openalex
    industry_tag: "医疗"           # ← 新增可选字段
    params:
      concepts: ["C71924100"]     # 医学相关 concept ID
  - id: openalex_energy
    connector: openalex
    industry_tag: "能源"
    params:
      concepts: ["C127413603"]    # 能源相关
```

**优先级**：`sources.yml industry_tag` > `connector.defaultIndustryTag` > `NULL`

### 4.3 采集时打标

`BaseConnector` 基类的 `collect()` 方法在组装 `RawDocument` 时，自动注入行业标签：

```typescript
// src/connectors/base.ts 中
protected buildRawDocument(data: RawDocumentData): RawDocument {
  return {
    ...data,
    industry_tag: this.resolvedIndustryTag ?? null,  // 从配置解析
  };
}
```

## 五、API 变更

### 5.1 `/api/search` 增加 `industry` 过滤参数

**请求**（扩展现有接口，向后兼容）：

```typescript
POST /api/search
{
  "query": "糖尿病治疗进展",
  "maxResults": 10,
  "industry": "医疗",          // ← 新增可选参数
  "industryStrict": false      // ← 可选：true=只返回有标签的结果，false=无标签结果也包含（默认false）
}
```

**响应**（各结果增加 `industryTag` 字段）：

```typescript
{
  "results": [
    {
      "id": "...",
      "title": "...",
      "snippet": "...",
      "score": 0.89,
      "industryTag": "医疗"   // ← 新增字段，可能为 null
    }
  ]
}
```

**检索行为**：

| `industry` 参数 | `industryStrict` | 行为 |
|----------------|-----------------|------|
| 未传           | -               | 全库检索（现有行为，不变） |
| `"医疗"`       | `false`（默认） | 行业匹配结果排序靠前，无标签结果也返回 |
| `"医疗"`       | `true`          | 只返回 `industry_tag = '医疗'` 的结果 |

**实现**：在 `hybridSearch` 中增加可选 WHERE 条件：

```sql
-- industryStrict=true 时增加条件
AND (dc.industry_tag = $industryTag)

-- industryStrict=false 时增加得分权重
ORDER BY (score + CASE WHEN dc.industry_tag = $industryTag THEN 0.2 ELSE 0 END) DESC
```

### 5.2 新增 `/api/admin/industry-tags/sync`（engine-core 代理写入）

**主包调用链**（v1.1）：行业激活/停用时，wangye 调 `engine-core` 的 `syncIndustryTags()`，由 engine-core 持 `DATA_PLATFORM_ADMIN_KEY` 转发本接口。**wangye 不直连**，不配置 `DATA_PLATFORM_ADMIN_KEY`。

```typescript
POST /api/admin/industry-tags/sync
Authorization: Bearer ${DATA_PLATFORM_ADMIN_KEY}   // 仅 engine-core → data-platform

{
  "industries": [
    { "name": "医疗", "isActive": true, "activatedAt": "2026-05-01T00:00:00Z" },
    { "name": "能源", "isActive": true, "activatedAt": "2026-03-15T00:00:00Z" },
    { "name": "新行业X", "isActive": false }
  ]
}

// 响应
{ "upserted": 3, "deactivated": 0 }
```

**主包调用时机**（经 engine-core）：
- 行业孵化激活（`SourceCategory.contentStatus` 变为 `ACTIVE`）
- 行业停用
- 新行业申请审核通过后创建

## 六、调度优先级（可选，Phase 2+）

活跃行业对应的数据源可配置更高采集频率。调度器在决定下次执行时间时，参考 `industry_tags.is_active`：

```yaml
# sources.yml 中对活跃行业源配置较高频率
- id: pubmed
  connector: pubmed
  industry_tag: "医疗"
  cron: "0 */4 * * *"    # 活跃行业：每4小时
  
- id: chembl
  connector: chembl
  industry_tag: "医疗"
  cron: "0 0 * * *"      # 次活跃：每天
```

动态调整（Phase 2+）：当主包通过 `sync` 接口将某行业标记 `isActive=false` 时，调度器可自动降频对应数据源。

## 八、与父仓 engine-core 的协作变更

Phase 2 完成后，engine-core 使用 data-platform SearchProvider 时可传入行业参数：

```typescript
// 主包 src/engine/defaultServices.ts 或 adapter 层
const searchProvider: SearchProvider = {
  id: "data-platform",
  search: async (query, opts) => {
    const res = await fetch(`${DATA_PLATFORM_URL}/api/search`, {
      method: "POST",
      body: JSON.stringify({
        query,
        maxResults: opts?.maxResults ?? 10,
        industry: opts?.industry,        // ← 新增：传入行业上下文
        industryStrict: false,           // 行业优先但不强制过滤
      }),
    });
    return (await res.json()).results;
  },
};
```

engine-core 工作流层在 `ctx.state.industry` 有值时，将其透传给 SearchProvider。
