## 1. 范围与原则

### 1.1 覆盖范围

| 类别 | `id` | 本方案 |
|------|------|--------|
| **已实现、默认关闭** | `worldbank`、`pubmed`、`semanticscholar` | §2 启用清单（无新 Connector） |
| **YAML 已登记、无 Connector** | `patentsview`、`sec_edgar`、`fred`、`clinicaltrials`、`github`、`hackernews` | §3–§8 分源实施 |
| **Legacy 占位** | `arxiv` | §9 不单独实现 |
| **未入 YAML（远期）** | `google_patents`、`reddit`、YouTube、Yahoo | §10 附录 |

**不做**：12 源一次性齐接；无业务需求的长尾源（FRED、HN）可长期 `enabled: false`。

### 1.2 实施铁律（接入点）

每新增 Connector 须同一主题 commit 完成：

| 步骤 | 路径 |
|------|------|
| 1 | `src/connectors/<id>.ts` + 可选 `*Helpers.ts` / `provenance/<id>.ts` |
| 2 | `src/connectors/index.ts` export |
| 3 | `src/connectors/bootstrap.ts` `registerConnector` |
| 4 | `config/sources.yml` 核对 `profile` / `enabled` |
| 5 | `src/processors/chunk.ts` 若新 `content_type` |
| 6 | `src/__tests__/unit/<id>.test.ts`（mock HTTP） |
| 7 | `docs/data-sources.md` 对应节 + 本方案 §变更记录 |
| 8 | `.env.example` + `CLAUDE.md` 环境变量表 |

父仓对接不阻塞 Connector：子包内用 **FixtureConnector 模式** 或 **unit mock** 即可；真源外网采集不进 CI（L3 可选脚本）。

### 1.3 波次总览

```
波次 0（运维）     启用 worldbank / pubmed / semanticscholar
波次 1（P2·RAG）   PatentsView → ClinicalTrials.gov
波次 2（P2·深度）  SEC EDGAR（全文 + 分块）
波次 3（P3·趋势）  GitHub → Hacker News
波次 4（P3·可选）  FRED（指标库，非 RAG 主路径）
```

| 波次 | 源 | 预估 | RAG 价值 |
|------|-----|------|----------|
| 0 | 3 个已有 Connector | 0.5d | 中–高 |
| 1 | patentsview + clinicaltrials | 3–4d | 高 |
| 2 | sec_edgar | 4–5d | 高（依赖 A8 全文分块） |
| 3 | github + hackernews | 2–3d | 中 |
| 4 | fred | 1–2d | 低（检索辅助，非向量主场景） |

## 3. PatentsView（`patentsview`）— 波次 1

### 3.1 价值与 RAG

| 项 | 说明 |
|----|------|
| 领域 | 美国专利（USPTO 清洗） |
| RAG | ⭐⭐⭐ `patent_abstract` 可直接 embedding |
| `content_type` | `patent`（`chunk.ts` 已预留） |
| YAML | `profile: rest_header_custom`，`PATENTSVIEW_API_KEY` |

### 3.2 API 与采集策略（USPTO ODP PFW）

- **API 主机**：`https://api.uspto.gov`
- **搜索**：`POST /api/v1/patent/applications/search`（body：`q`、`rangeFilters`、`filters`、`fields`、`pagination`）
- **认证**：Header `X-API-KEY`；ENV `USPTO_ODP_API_KEY`（[Getting Started](https://data.uspto.gov/apis/getting-started)）
- **collect**：默认 `grantDate` ≥ `since`（近 7 天）+ 状态 `Patented Case`；`offset`/`limit` 分页
- **externalId**：`applicationNumberText`
- ~~`PATENTSVIEW_API_KEY` / PatentSearch~~ 已移除

详见 `docs/data-sources.md` §2.3。

### 3.3 rawJson 最小集

```typescript
{
  title: patent_title,
  abstract: patent_abstract,
  publication_date: patent_date,  // YYYY-MM-DD
  type: "patent",
  url: `https://patentsview.org/patent/${patent_id}`,
  patent_id,
  assignee_organization?,
  inventors?: string[],
}
```

### 3.4 文件清单

| 文件 | 内容 |
|------|------|
| `src/connectors/patentsview.ts` | `PatentsViewConnector` |
| `src/connectors/provenance/patentsview.ts` | D5：`POST` body 合成 curl（**待建**） |
| `src/__tests__/unit/patentsview.test.ts` | mock `fetch` 分页 + 字段映射 |

**ENV**：`USPTO_ODP_API_KEY` → `factory.ts` → Header `X-API-KEY`。

## 4. ClinicalTrials.gov（`clinicaltrials`）— 波次 1

### 4.1 价值与 RAG

| 项 | 说明 |
|----|------|
| 领域 | 全球临床试验注册 |
| RAG | ⭐⭐⭐⭐ `briefSummary` / `detailedDescription` |
| `content_type` | `clinical_trial` |
| YAML | `profile: rest_none` |

### 4.2 API 与采集策略

- **Base**：`https://clinicaltrials.gov/api/v2/studies`
- **搜索/collect**：`GET ?query.term=...&pageSize=100&pageToken=...`
- **分页**：`pageToken`（非 offset）→ 新增 `BaseConnector.paginatePageToken()` 或源内私有循环
- **增量**：`filter.advanced` 或 `query.term` 结合 `LastUpdatePostDate`（需对照 v2 文档字段名）
- **externalId**：`NCTId`（如 `NCT01234567`）

### 4.3 rawJson 最小集

```typescript
{
  title: briefTitle || officialTitle,
  abstract: [briefSummary, detailedDescription].filter(Boolean).join("\n\n"),
  publication_date: startDate,  // 或 lastUpdatePostDate
  type: "clinical-trial",
  url: `https://clinicaltrials.gov/study/${nctId}`,
  nct_id: NCTId,
  phase?, conditions?, interventions?,
}
```

### 4.4 文件清单

| 文件 | 内容 |
|------|------|
| `src/connectors/clinicaltrials.ts` | 主 Connector |
| `src/connectors/clinicaltrialsHelpers.ts` | 响应扁平化（`protocolSection` 等嵌套） |
| `src/__tests__/unit/clinicaltrials.test.ts` | fixture JSON |

**速率**：≤10 RPS → `RateLimiter.fromRPS(8)` 留余量。

## 5. SEC EDGAR（`sec_edgar`）— 波次 2

### 5.1 价值与 RAG

| 项 | 说明 |
|----|------|
| 领域 | 美股上市公司申报（10-K/10-Q/8-K） |
| RAG | ⭐⭐⭐⭐ 全文 HTML，**必须**走 `paperChunks` + `rawJson.fulltext` |
| `content_type` | `company_filing` |
| YAML | `profile: rest_polite`（实为 **User-Agent 强制**，非 mailto） |

### 5.2 API 与采集策略（两阶段）

**Phase A — 元数据 + 索引（MVP）**

1. EFTS：`GET https://efts.sec.gov/LATEST/search-index?q=...&forms=10-K&dateRange=custom&startdt&enddt`
2. 或 `GET https://data.sec.gov/submissions/CIK{cik}.json` 拉最近 filing 列表
3. `rawJson`：title（公司名 + form + date）、abstract（item 1 摘要片段或空）、`url` 指向 `Archives/edgar/data/...`

**Phase B — 全文（推荐与 A8 同周）**

1. 下载 primary document HTML（遵守 10 req/s，间隔 ≥150ms）
2. HTML → 纯文本段落写入 `rawJson.fulltext`
3. `chunk.ts` 已有 `pickBodyText` 读 `fulltext`

### 5.3 约束

- **User-Agent**：`SEC_EDGAR_USER_AGENT` 环境变量（公司名 + 邮箱），否则 403
- **禁止**裸爬：须遵守 [SEC 公平访问政策](https://www.sec.gov/os/webmaster-faq#developers)
- **externalId**：`accession_number` 去横线或 `cik-accession` 组合键

### 5.4 文件清单

| 文件 | 内容 |
|------|------|
| `src/connectors/secEdgar.ts` | Connector + collect |
| `src/connectors/secEdgarHelpers.ts` | EFTS 解析、HTML strip |
| `src/processors/secFilingText.ts`（可选） | HTML 清洗 |
| `src/__tests__/unit/secEdgar.test.ts` | mock 索引 JSON |

**预估**：Phase A 2d + Phase B 2–3d。

## 6. GitHub（`github`）— 波次 3

### 6.1 价值与 RAG

| 项 | 说明 |
|----|------|
| 领域 | 开源仓库与技术趋势 |
| RAG | ⭐⭐⭐ README + description；非论文级深度 |
| `content_type` | `tech_activity` |
| YAML | `profile: rest_bearer` → `GITHUB_TOKEN` |

### 6.2 实施选型

| 方案 | 优点 | 缺点 |
|------|------|------|
| **REST** `search/repositories` | 与现有 BaseConnector 一致 | 字段粗、多次请求补全 README |
| **GraphQL** `profile: graphql_github` | 一次取 stars/language/readme | 需单独 `fetchGraphQL`、点数计费 |

**推荐 MVP**：REST 搜索 + 可选 `GET /repos/{owner}/{repo}/readme`（Base64 解码）作为 `abstract`。

### 6.3 collect 策略

- `query` → `search/repositories?q=${encodeURIComponent(query)}&sort=updated&per_page=100`
- 增量：`since` → `pushed:>${since}` 限定（GitHub 搜索语法）
- **externalId**：`owner/repo`

### 6.4 rawJson 最小集

```typescript
{
  title: full_name,
  abstract: description || readme_excerpt,
  publication_date: pushed_at,
  type: "repository",
  url: html_url,
  stars: stargazers_count,
  language: language,
}
```

## 7. Hacker News（`hackernews`）— 波次 3

### 7.1 价值与 RAG

| 项 | 说明 |
|----|------|
| 领域 | 技术社区热点 |
| RAG | ⭐⭐ 标题 + 外链文章需二次抓取（**MVP 仅 HN 元数据**） |
| `content_type` | `tech_activity` |
| YAML | `profile: firebase_rest` |

### 7.2 API 与采集策略

Firebase REST（无 Key）：

```
GET /v0/topstories.json          → id 列表
GET /v0/item/{id}.json           → 单条（title, url, text, time）
GET /v0/maxitem.json             → 增量上界
```

- **collect**：拉 `topstories` 前 N 或 `since` 对应 time 过滤
- **速率**：礼貌 1–2 RPS（Firebase 无硬限但避免封禁）
- **externalId**：`String(id)`

### 7.3 rawJson

```typescript
{
  title: title || `HN #${id}`,
  abstract: text?.slice(0, 2000) || "",
  publication_date: new Date(time * 1000).toISOString().slice(0, 10),
  type: "forum_post",
  url: url || `https://news.ycombinator.com/item?id=${id}`,
  score,
  descendants,
}
```

**二期**：外链 `url` 为文章时，可选 readability 抽取（超出 MVP）。

## 8. FRED（`fred`）— 波次 4（可选）

### 8.1 价值与 RAG

| 项 | 说明 |
|----|------|
| 领域 | 美联储经济时间序列 |
| RAG | ⭐ 无数值向量语义；**关键词 + 元数据检索** |
| 与 worldbank | 同属 `economic_indicator`；实现可复用 `worldbank` 模式 |
| YAML | `profile: rest_query_param_key`，`FRED_API_KEY` |

### 8.2 采集策略

1. `series/search?search_text=` 得 `seriess`
2. 对每条 `series/observations?series_id=&observation_start=` 拉观测
3. **abstract** 合成：`${title}\n${notes}\n最新值: ${lastValue} (${date})`
4. **不建议**对观测序列做 embedding；入库供结构化查询与图表
