# 集成测试最小闭环方案（I 轨）

> 2026-05-19 定稿 · **不依赖望野父仓**  
> 目标：在本仓库内验证「采集 → 入库 → 向量化 → 检索 → SearchProvider 消费」完整链路，替代 C2/C3 联调前的平台断层验证。  
> **代码进度真源**：[实施进度总览.md](./实施进度总览.md) §3 I 轨

---

## 1. 背景与动机

### 1.1 现状缺口

| 层级 | 命令 | 已有能力 | 缺口 |
|------|------|----------|------|
| **L0** | `pnpm test:run` | 单元 + integration/api inject（mock DB/RAG） | 不碰真 PostgreSQL |
| **L2-live** | `pnpm test:live` | migrate → serve → health/schedules/search | **无 collect**；空库 search |
| **L2.5** | `integration/embed.test.ts` | Ollama bge-m3 单测 | 未接入 dedup / hybridSearch |
| **C2/C3 替身** | `integration/api/search-provider.test.ts` | mock `fetch` 契约 | 未对**真 serve** HTTP 闭环 |

`docs/phase1-plan.md` §六 描述的 4 步 curl（collect → jobs → search）**无自动化**；接父仓 C2/C3 前缺少子包内可重复的门禁。

### 1.2 设计目标

**一条命令**（`pnpm test:integration`）验证：

```
FixtureConnector.collect
  → Scheduler.trigger → dedup → embedDocuments
  → hybridSearch（真 pgvector + tsvector）
  → createDataPlatformSearchProvider(baseUrl).search()  # C2/C3 替身
```

**刻意不包含**（降低复杂度）：

- 真实 OpenAlex / PubMed 外网（不稳定、慢、需 Key）
- 父仓 `DataPlatformClient` / engine-core 工作流注入
- A12 re-embed 回填、A8 段落分块

**刻意包含**（走真实代码路径）：

- 真 PostgreSQL + pgvector（Docker `:5433`）
- 真 `Scheduler` / `dedup` / `vectorStore.embedDocuments` / `retriever.hybridSearch`
- 真 Fastify `buildApp` + HTTP `POST /api/search`

## 3. 核心组件

### 3.1 FixtureConnector（零外网）

固定 3 条 `RawDocument`，含可断言的唯一关键词；**不**写入 `config/sources.yml`，**不**进入 `registerDefaultConnectors`。

| externalId | title 关键词 | abstract 关键词 |
|------------|-------------|----------------|
| `fixture-w1` | Transformer Attention | self-attention parallel |
| `fixture-w2` | CRISPR Gene Editing | Cas9 nuclease |
| `fixture-w3` | World Bank GDP Indicator | economic time series |

```typescript
// src/__tests__/fixtures/fixtureConnector.ts（待建）
export class FixtureConnector extends BaseConnector {
  readonly meta = { id: "fixture", baseUrl: "fixture://local", ... };
  async *collect(_params: CollectParams): AsyncGenerator<RawDocument> {
    for (const doc of FIXTURE_DOCS) {
      yield { sourceId: "fixture", externalId: doc.externalId, rawJson: doc.rawJson, fetchedAt: new Date() };
    }
  }
  async search(query: string): Promise<SearchResult[]> { /* 内存过滤 FIXTURE_DOCS */ }
}
```

Harness 内：`scheduler.registerConnector({ id: "fixture", create: () => new FixtureConnector(...) })`。

### 3.2 Mock Embedding 后端（L2-fast / CI）

在 `src/rag/embed.ts` 新增 `EMBED_BACKEND=mock`：

- 同一输入文本 → 同一 1024 维向量（hash 扩维 + L2 归一化）
- **不要求**语义相近文本向量相近；集成测依赖 **关键词路径（tsvector）** 与「向量写入不报错」
- CI 无需 Ollama，单次 ~30s

| 模式 | 环境变量 | 依赖 | 用途 |
|------|----------|------|------|
| `mock` | `EMBED_BACKEND=mock` | 仅 DB | L2-fast，`pnpm test:integration` |
| `ollama` | `EMBED_BACKEND=ollama`（默认） | DB + Ollama bge-m3 | L2-full，本地/夜间 |
| `openai` / `voyage` | 现有 | 外网 Key | 不参与 I 轨 |

### 3.3 测试 Harness

```typescript
// src/__tests__/integration/helpers/harness.ts（待建）
export async function withIntegrationHarness(
  fn: (ctx: { scheduler: Scheduler; app: FastifyInstance; baseUrl: string }) => Promise<void>,
): Promise<void> {
  await clearPlatformData({ includeConfig: false });
  const scheduler = new Scheduler();
  scheduler.registerConnector({ id: "fixture", create: () => new FixtureConnector(...) });
  const app = await buildApp({ scheduler, logger: false });
  await app.listen({ port: 0, host: "127.0.0.1" });
  const addr = app.server.address() as AddressInfo;
  const baseUrl = `http://127.0.0.1:${addr.port}`;
  try {
    await fn({ scheduler, app, baseUrl });
  } finally {
    await app.close();
    await clearPlatformData({ includeConfig: false });
  }
}
```

**DB 隔离（最小方案）**：共用 `data_platform` 库；用例前后 `clearPlatformData()`；vitest `fileParallelism: false`（integration 目录）。

**进阶**：`TEST_DATABASE_URL=.../data_platform_test` + `docker-compose.test.yml`（`:5434`），并行时再引入。

### 3.4 主闭环用例

```typescript
// src/__tests__/integration/pipeline/closed-loop.test.ts
describe("I 轨：pipeline closed loop", () => {
  itIfDb("collect → embed → search → SearchProvider", async () => {
    process.env.EMBED_BACKEND = "mock";
    await withIntegrationHarness(async ({ scheduler, baseUrl }) => {
      const job = await scheduler.trigger("fixture", "");
      expect(job.status).toBe("success");
      expect(job.itemsCollected).toBe(3);

      await waitForChunks(3); // mock 同步；ollama 轮询 document_chunks

      const res = await fetch(`${baseUrl}/api/search`, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ query: "transformer attention", maxResults: 5 }),
      });
      const body = await res.json();
      expect(body.results.some((r: { title: string }) => r.title.includes("Transformer"))).toBe(true);

      const provider = createDataPlatformSearchProvider(baseUrl);
      const viaAdapter = await provider.search("transformer attention");
      expect(viaAdapter[0]?.title).toContain("Transformer");
    });
  });
});
```

**无 DB 时**：`beforeAll` 检测 `pg_isready :5433` 或 `SELECT 1`；失败则 `it.skip` 或整个文件 skip（与 `embed.test.ts` 一致）。

## 5. 与 C2/C3 / 父仓的对应

## 7. 质量门禁（接 C2/C3 前）

```
必须：pnpm test:run                    # L0
推荐：pnpm test:integration            # L2-fast，Docker DB
```

**接父仓 C2/C3 前**：L0 + L2-fast 通过即可认为子包闭环就绪；L2-live 仍作 serve 运维探活。
